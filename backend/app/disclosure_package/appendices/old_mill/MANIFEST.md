# Old Mill 2026 — Static Appendix Manifest

**Source of truth:** `backend/app/disclosure_package/package_specs/old_mill.py`
(`OLD_MILL_2026.entries` — `StaticAppendix(...)` entries).

**Golden reference PDF:** `2026/Old Mill 2026 budget disclosure.pdf` (109 pages
total; 31 generated + 78 static).

This manifest is the provenance record for each static appendix the merge
pipeline (`merge.py` + `compiler.py`) consumes. Phase 11 plan 11-05 Task 2
is the human-supervised extraction step — running `qpdf --pages` on the
golden PDF to populate this directory with real boilerplate. Until that
step is approved by Tri-State legal review, the appendix files are NOT
present and `compiler.compile_package` will fail at preflight (REQ-D11-008).

## Extraction protocol

Run from the **repo root** (the golden PDF lives in `2026/`):

```bash
APPDIR="backend/app/disclosure_package/appendices/old_mill"
GOLDEN="2026/Old Mill 2026 budget disclosure.pdf"

# Example — pages 46-48 (insurance certificate, 3 pages)
qpdf "$GOLDEN" --pages "$GOLDEN" 46-48 -- --empty - > "$APPDIR/insurance_certificate.pdf"

# After all 23 files are extracted, verify each is structurally valid:
for f in "$APPDIR"/*.pdf; do qpdf --check "$f" || echo "FAIL: $f"; done

# And verify the per-appendix page count matches `page_count_hint`:
for f in "$APPDIR"/*.pdf; do
  printf "%-40s %s\n" "$(basename "$f")" "$(pdfinfo "$f" | grep ^Pages)"
done
```

## Legal / CCRs review checklist

Before extracted PDFs are committed to the repository OR baked into the
backend Docker image, Tri-State must confirm:

- [ ] All statutory text reproductions (entries 2, 3, 4, 5, 6, 22, 23) are
      verbatim from the cited California Civil Code section or are
      derivative documents the company already publishes — no
      copyright-encumbered third-party material.
- [ ] All CC&R / Rules & Regulations reproductions (entries 7–21) match
      the latest board-approved version. The golden PDF is from 2025 — if
      any rule has been amended since, the appendix needs to be re-issued
      from the current source.
- [ ] The placeholder `appendix_pages_74_87.pdf` either (a) names the
      actual sub-documents in that range so the manifest can split it into
      named entries, OR (b) is approved as a single multi-section appendix
      file shipping unchanged from the 2025 disclosure.
- [ ] Insurance certificate (entry 2) is the **current** policy term — if
      the insurance year does not align with the disclosure fiscal year
      the certificate must be re-extracted from the most recent COI.

## Storage decision (RESEARCH risk #16)

**Phase 11 ships these PDFs in the Docker image, not in git.**

Rationale: each appendix is small (most are 1–6 pages of low-DPI scanned
content, ~50–500 KB). The aggregate is ~5–10 MB which is fine to bundle
in the image but bloats the repo's `git clone` for everyone — and the
contents change on a CC&R-amendment cadence (years), not on a code-change
cadence (days). Keeping them out of git also avoids accidental leakage
of any PII (signatures, account numbers) that might have crept into the
golden PDF.

The Dockerfile copies them into `/app/app/disclosure_package/appendices/old_mill/`
during build. Production deployments must include this directory; the
preflight gate (`preflight.validate_inputs(appendices_root=...)`) raises
a blocking error if any appendix is missing at runtime.
